# Domain docs

This is a single-context repository.

Before engineering work, read the root `CONTEXT.md` and the ADRs under `docs/adr/` that apply to the area being changed. Use the glossary's canonical terms in code, tests, issues, and documentation.

If a proposed change conflicts with an ADR, identify that conflict explicitly instead of silently overriding the decision. Missing domain documentation is not a blocker; proceed and note a genuine terminology or decision gap if one becomes material.
