# VKF 0.1.6 — Strict Vector Lifting And Axis Reductions

VKF 0.1.6 replaces compatibility-filtered aggregate broadcasting with a
smaller, stricter rule: ordinary typed functions may lift recursively through
vectors, while tuples and records remain explicit whole values.

## What changed from 0.1.5

- Automatic lifting descends only through fixed or dynamic vector layers.
- A lifted element must match the function parameter type exactly. Ordinary
  scalar conversions still apply to direct calls, but do not select vector
  leaves.
- Tuples and records are atomic. Their arithmetic requires an explicit operator
  overload instead of silently transforming selected fields.
- Exact whole-container matches still take priority. A row function can
  therefore map over a matrix without a user-written loop.
- Unary and binary overload families are resolved from typed aliases before
  machine lowering. The backend no longer guesses that an arbitrary aggregate
  should use an unrelated overload.
- Higher-order callables and generic multiset containers retain safe,
  arity-aware overload fallback when their frontend representation is erased.
- `stat.sum` reduces all nested vector dimensions when `axis` is omitted.
- `stat.sum(axis:)` accepts one constant integer or a nonempty tuple of constant
  integers for fixed rectangular numeric vectors. Negative axes count from the
  last dimension; duplicates and out-of-range axes are compile errors.
- Sum results retain the numeric vector leaf type when it is statically known.
- Landing-page benchmark tables now present measurements and same-host ratios
  without exposing internal acceptance thresholds or pass labels.
- Relative performance targets remain available as explicit development checks;
  release evidence collection does not turn runner-specific ratios into a
  correctness verdict.

## Verification

- 320 native VKF tests pass with zero failures.
- The suite includes explicit rejection coverage for tuple/record lifting,
  conversion-selected vector leaves, implicit record arithmetic, duplicate and
  out-of-range axes, and tuple arguments to `stat.sum`.
- Positive coverage includes fixed and dynamic vector lifting, nested vectors,
  vector-of-record calls, row functions over matrices, recursive full sums,
  integer/negative/tuple axes, alias-aware overloads, integer variadic sums,
  resource ownership, and multiset arithmetic.
- All 59 documented programs are rebuilt and executed as part of release proof.
- Windows x64, Linux x64, and macOS ARM64 proof reports bind outputs and timing
  samples to exact source and compiler hashes.
- The latest [same-host Linux comparison](../../benchmarks/core-comparison/results/linux-x64-016.md)
  and [256-policy Windows landscape](../../benchmarks/policy-landscape/evidence/windows-x64-v0.1.6-ci.md)
  are retained with the release evidence, including every timing sample and
  code hash.

## Native scope

The included native modules remain `math`, `stat`, `random`, `time`, `io`,
`collections`, `errors`, `system`, `process`, and `regex`. `physics`, `ui`, and
`symbolic` remain excluded rather than shipping partial implementations.
