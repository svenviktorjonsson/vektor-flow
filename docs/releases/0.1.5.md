# VKF 0.1.5 — Adaptive Native Optimization

VKF 0.1.5 makes native optimizer choices explicit, independently selectable,
and measurable per program instead of forcing one global recipe onto every
workload.

## What changed from 0.1.4

- Eight legal lowering switches define 256 optimizer policies.
- Every empirical candidate is executed and compared with the scalar policy
  before its timing can be selected.
- Policies that emit byte-identical machine code share one measurement. This
  preserves the logical landscape without wasting the compilation budget on
  aliases.
- Successful tuning stores the selected policy under a fingerprint of the
  exact program and target features. Normal search is bounded by the remaining
  compilation-time budget; exhaustive landscape mode is explicit.
- Recognized fixed-width triangular matrix reductions use AVX2 packed
  denominator generation, division, and accumulation with scalar remainders.
- Recognized dual-dot reductions calculate numerator and denominator in packed
  lanes, then preserve scalar remainder elements and reduction semantics.
- Aggregate parameter borrowing and direct aggregate-result forwarding avoid
  unnecessary copies where ownership is proven safe.
- Proven integer locals, native index addressing, parity specialization, and
  fused multiply-add are independently selectable.
- The Windows x64 packed emitter uses only volatile XMM/YMM registers across
  generated entry calls, preserving the Windows ABI.
- Eleven native VKF optimizer tests cover affine and structural maps, integer
  induction, parity, aggregate forwarding, both matrix orientations, packed
  dual-dot reductions, non-vector-width remainders, and resource-owning
  aggregate calls across runtime boundaries.

## Policy landscape evidence

The committed [Windows x64 spectral-norm landscape](https://github.com/svenviktorjonsson/vektor-flow/blob/main/benchmarks/policy-landscape/evidence/windows-x64-v0.1.5.md)
retains every one of the 256 policies, their machine-code hashes, result checks,
and mean ± standard deviation. In the measured run, all 256 policies were
correct and collapsed to 18 distinct binaries. The fastest legal policy basin
was 2.64× faster than the slowest.

The exact release-compiler run selected `mask-8e`, which emits the same machine
code and recorded the same 8.535 ± 3.433 ms as the all-enabled `mask-ff`
policy. Earlier repeated experiments selected different masks within the same
fast basin, confirming that small differences inside it are noise-sensitive.
The release therefore claims the large policy-basin effect, not a universal
winning mask.

## Verification contract

Release publication requires:

- 309 native VKF tests on Windows x64, Linux x64, and macOS ARM64;
- every documented program compiled 100 times and run 100 times on all three
  release targets with exact output and source/compiler hashes;
- the pinned 100-run seven-language comparison on Linux x64;
- all 256 policies correct in the committed Windows x64 landscape;
- direct compiler lowering with no Python, C++ compiler, assembler, linker, or
  compatibility fallback at user compile time or runtime.

The historical 20,000-operation scalar engineering gate remains under 10 ms
mean compiler-core time and 500 microseconds mean raw runtime. It is not a
language-ranking benchmark.

## Native scope

Native library scope remains `math`, `stat`, `random`, `time`, `io`,
`collections`, `errors`, `system`, `process`, and `regex`. `physics`, `ui`, and
`symbolic` remain excluded rather than shipping partial implementations.
