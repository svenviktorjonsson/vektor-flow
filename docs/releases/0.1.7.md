# VKF 0.1.7 — Wider SysV Numeric Register Cache

VKF 0.1.7 improves the general x64 backend for hot numeric functions and
replaces the landing-page comparison with one controlled, higher-sample report.

## What changed from 0.1.6

- Call-free numeric functions on the SysV x64 ABI can cache hot locals in
  XMM6 through XMM15 instead of only XMM6 and XMM7.
- Register-to-register packed moves support high XMM registers with the correct
  REX encoding.
- Windows keeps XMM6/XMM7 because XMM6 through XMM15 are nonvolatile in the
  Windows x64 ABI and would otherwise require preservation.
- The optimization is general backend allocation. It does not recognize or
  special-case benchmark source.
- The landing README has one timing table. It reports VKF mean plus sample
  standard deviation and same-host `VKF / competitor` ratios for C, Rust, and
  Zig; the linked report retains every raw sample.
- The controlled comparison measures 1,000 raw-kernel runs after 50 warmups in
  one pinned Linux x64 environment.

## Verification

- 320 native VKF tests pass with zero failures.
- The documented-program suite is rebuilt and run on Windows x64, Linux x64,
  and macOS ARM64.
- Comparison programs verify exact output before timing.
- Source hashes, executable hashes, compiler identity, toolchain versions,
  environment, and all timing samples are retained in the evidence reports.
- The controlled [same-host comparison](../../benchmarks/core-comparison/results/linux-x64-017-controlled-1000.md)
  contains the published front-page measurements.

## Native scope

The included native modules remain `math`, `stat`, `random`, `time`, `io`,
`collections`, `errors`, `system`, `process`, and `regex`. `physics`, `ui`, and
`symbolic` remain excluded rather than shipping partial implementations.
