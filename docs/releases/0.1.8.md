# VKF 0.1.8 — Compact Indexing And Pipe Assignment

VKF 0.1.8 makes the compact source style part of the verified compiler surface.

## Language And Compiler

- `values.index` selects a vector position when `index` is a bound `int` or
  `num`.
- `values.(expression)` remains the form for computed indices, multiple
  indices, and special values such as `$`.
- A range pipe may contain indexed assignment directly:

  ```vkf
  ..n - 1 >> working.($): permutation.($)
  ```

- The assignment runs once per range element. If another `>>` follows, it
  receives the value that was stored by the preceding assignment.
- Record fields remain ordinary named fields. Compact dynamic indexing is only
  selected when the left value is a vector and the right name is a bound
  numeric index.

## Canonical Examples And Documentation

- The Fannkuch copy and shift loops now use range pipes instead of manually
  declared and incremented loop indices.
- Discarded finite range pipes lower to counted machine loops without allocating
  or concatenating a result vector.
- Public benchmark, guide, architecture, and example sources use `.index` for
  simple bound indices and retain parentheses only for computed indices.
- The landing README now includes a basic syntax reference and a complete
  while-loop plus repeated-match example with exact output.

## Native Optimization

- Numeric functions whose only errors terminate the function can retain hot
  scalar locals in registers; catchable errors and owned values keep the
  conservative stack-backed path.
- Floating locals used as indexed-address operands are excluded from the
  register cache, preventing stale stack indices under tuner-selected policies.
- Call-free SysV x64 numeric functions cache hot values in XMM8 through XMM15;
  XMM0 through XMM7 remain reserved for expression and scratch lowering.

## Verification

- The native VKF suite includes regressions for range-pipe indexed assignment,
  compact named indexing, and assignment values piped onward.
- The Windows x64 native suite reports `323 passed, 0 failed`.
- Every documented program is compiled from 10 fresh paths and executed in 10
  fresh operating-system processes on Windows x64, Linux x64, and macOS ARM64.
- Every round must return the same exit code and byte-identical stdout and
  stderr. This release does not use per-example timing as a quality claim.
- The controlled Linux x64 comparison uses the 0.1.8 compiler, 50 warmups, and
  1,000 measured raw samples per language and kernel. Every VKF/C, VKF/Rust,
  and VKF/Zig ratio is below 2× across spectral norm, Fannkuch, and N-body.
- Full samples, hashes, toolchains, and machine conditions are stored in
  [`linux-x64-018-controlled-1000.json`](../../benchmarks/core-comparison/results/linux-x64-018-controlled-1000.json).

VKF remains an unsupported experimental preview. `physics`, `ui`, and
`symbolic` are still excluded from the native release.
