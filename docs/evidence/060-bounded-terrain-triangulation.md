# Bounded resident-cell triangulation and emitted bounds

2026-09-05; base `3bc7c46cd2568520f09ae6912ddbd59564616d4a`, branch `pre-gen`.

## Private demand consumer

The existing immutable terrain surface packet now feeds a bounded triangulation
consumer. Tile/refinement metadata stays with the original terrain owner.
Surface positions must match that source bit-for-bit, material lengths must
align, normals must be finite, and refinement must agree with potential count.
These checks happen before topology allocation. No height, normal, or material
is regenerated by this consumer.

The caller supplies an ordered list of local row-major cell IDs and explicit
cell/triangle budgets. Each selected fully resident cell emits the same two
upward triangles: `[a,c,b]`, `[b,c,d]`, with corners `a,b,c,d` in row-major order.
All indices address the retained surface packet. No vertex buffers are copied.

Selection is the prefix limited by demand length, cell budget, and half the
triangle budget. An odd budget never emits half a cell. Limits are 65,536
demand entries/cells and 131,072 triangles. Only selected cells are checked for
domain, complete residency and duplicates, in caller order; unselected cells
are not evaluated. Missing corners are rejected, not generated or skipped.
The duplicate lookup is bounded by selected demand; hash iteration never
controls output. All selected cells validate before triangle storage is reserved.

Axis-aligned bounds enclose **emitted linear triangles only**. They do not bound
the continuous height field, undemanded vertices, or potential terrain. Empty
demand has no bounds. Mixed signed-zero ties select negative zero for minima
and positive zero for maxima, so permuting the same cells cannot change bound
bits. There are no camera, visibility, projected-error or LOD-selection rules.

## RED → GREEN

1. One-cell topology/bounds test failed because the triangulation header was absent.
2. Forged surface coordinates were accepted; exact source-position alignment
   now rejects them before allocation.
3. A forged NaN normal was accepted; existing finite-normal rejection now
   protects this consumer too.
4. Changed refinement with the old potential count was accepted; inconsistent
   grid identity now fails clearly.
5. Repeated demand emitted duplicate triangles; selected duplicate cells now
   produce `terrain cell demand is duplicated`.
6. Reversing generated flat cells changed signed-zero bound bits. Canonical
   zero ties made exact permutation tests GREEN without changing any positions.

The behavioral REDs were explicit exit-1 failures, not weakened expectations.
Captures are `build/terrain/10-triangulation-red.txt` through
`15-triangulation-zero-red.txt`. Existing error messages, terrain sampling,
normal sampling and water-level material selection are unchanged.

The oracle compares every position, normal, material ID, triangle index, bound,
count and truncation word. Native tests check both shared-edge directions,
preserved coarse anchors, replay, changed seeds, winding and source ownership.
Exact rejection order, missing corners, empty/odd/prefix/full budgets and
duplicate demands are included. The triangle vector's observed capacity equals
its emitted count on all three toolchains; empty topology reserves nothing.

The maximum fully resident fixture uses 65,536 existing surface samples and
65,024 demanded cells: 130,048 triangles, 1,560,576 topology bytes. Its complete
probe trace is 4,968,540 bytes, within the unchanged 16 MiB capture limit.
Refinement 16 still represents 4,295,098,369 potential samples without allocating
them; demanding a cell lacking its complete row of corners fails explicitly.

All eight original terrain/material SHA-256 gates remain unchanged, including
the full trace `e1c0539a8261acd4b6032b19a40492a139af315e64956a0ab3af791d231807e6`.
The existing normal differential remains intact. No forest, road, stone,
public VKF syntax/API/schema/default, or language diagnostic is changed.

## Reproduce and sanitizer qualification

```sh
node --test tests/js/vf-terrain-water-level-native.test.mjs
g++ -std=c++20 -O1 -g -ffp-contract=off -Wall -Wextra -Werror -pedantic -fsanitize=address,undefined -fno-omit-frame-pointer -no-pie -I. native/material/vf_terrain_triangulation_test.cpp -o build/terrain/triangulation-sanitized
build/terrain/triangulation-sanitized
```

Repeat each height/normal/triangulation sanitizer executable twenty times,
requiring exit 0 and empty stderr. No sanitizer options or checks are disabled.
`-no-pie` retains the previously documented [PIE startup isolation](060-conditioned-terrain-normals.md);
ordinary PIE instability is not relabeled GREEN. The final 60-run receipt is
`build/terrain/triangulation-signed-zero-sanitizer-20.json`.

The probe uses strict `-O2 -ffp-contract=off` GCC/Clang builds or MSVC
`/O2 /fp:strict /W4 /WX /EHsc /std:c++20`. `VKF_TERRAIN_PROBE` selects a
separate compiled executable per toolchain. `--triangles` adds the topology
trace; original default and `--normals` modes retain their previous bytes.

## Still outside this packet

Camera selection, continuous-field conservative bounds, projected geometric
error, mixed-level edge stitching, geomorphing, a renderer, mountains, erosion,
physical shore/water behavior and public author controls remain separate.
Same-level seam identity and coarse anchors do not prove crack-free adaptive
LOD. There is no performance, naturalism, LOD-quality or release-percentage claim.
